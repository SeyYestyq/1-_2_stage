# Контракты модуля «Ядро и конструктор видов»

Источник: личный документ «01_Angelina», модульный план «07_Module_Plan» (раздел 2 «Контракты» и раздел 5 «Подзадачи»), стандарты 1С «06_ITS_Standards».
Этот файл — то, на что опираются все: Денис (формы), Юрий (печать), Дамир (тесты), Максим (движок).

## Общие договорённости (менять только через Ангелину)

1. Статусы и события — **только значения перечислений**: `Перечисления.СтатусыДокументов`, `Перечисления.СтатусыНастройкиВида`, `Перечисления.РешенияСогласования`, `Перечисления.СобытияСогласования`. Никаких строк «Согласован» в коде.
2. Ошибки — **массив структур** `{Поле, Текст}`, все ошибки сразу, пустой массив = ошибок нет. `Поле` — имя реквизита, табличной части, поля вида или строки JSON-пути; для общих ошибок — пустая строка.
3. Порядок полей — реквизит `Порядок` в `ВидыДокументов.Поля`; в коде не сортировать «на глаз», только по `Порядок`.
4. Один универсальный документ `ДокументСЭД`; поля вида — данные (ПВХ `ПоляДокументов` + ТЧ), не метаданные.
5. Документ не проводится (`Posting = Deny`). Статус — реквизит `Статус`.

## Общий модуль `КонструкторВидов` (сервер, вызов сервера)

### `ПоляВида(Вид) → ТаблицаЗначений`
Колонки: `Поле` (ПланВидовХарактеристикСсылка.ПоляДокументов), `Заголовок` (Строка), `Идентификатор` (Строка — имя поля для формы и JSON), `ТипПоля` (ПеречислениеСсылка.ТипыПолей), `ТипЗначения` (Тип: Строка / Число / Дата / СправочникСсылка.ЗначенияПолей), `Обязательное` (Булево), `Порядок` (Число).
Правила:
- строки отсортированы по `Порядок`, затем по `Заголовок`;
- `Скрыто = Истина` — поля в результат **не попадают** (данные старых документов сохраняются, в форму и печать поле не идёт);
- `Обязательное` берётся из ТЧ `ВидыДокументов.Поля`, `Заголовок`/`ТипПоля` — из элемента ПВХ;
- принимает и **незаписанный** вид (объект в памяти) — нужно для предпросмотра формы и для проверки шаблона до записи;
- пустой вид → пустая таблица значений с теми же колонками.

### `ПроверитьШаблон(Вид) → Массив {Поле, Текст}`
Принимает объект `СправочникОбъект.ВидыДокументов` (в том числе незаписанный). Возвращает **все** ошибки сразу. Проверки (по одной структуре на каждую ошибку):
1. пустое `Наименование` → `{Поле: "Наименование"}`;
2. не заполнена `Категория` → `{Поле: "Категория"}`;
3. ни одного поля в ТЧ `Поля` (скрытые не считаются) → `{Поле: "Поля"}`;
4. повторяется идентификатор поля → `{Поле: "Поля", Текст: «Поле «X» указано дважды»}`;
5. у поля с `ТипПоля = ВыборИзСписка` меньше двух значений в `ЗначенияПолей` → `{Поле: "Поля"}`;
6. в маршруте меньше двух этапов → `{Поле: "Маршрут"}`;
7. в строке маршрута не указан согласующий → `{Поле: "Маршрут"}`;
8. в маршруте меньше двух **разных** сотрудников (кейс: «не менее двух согласующих сотрудников»; два этапа с одним человеком не проходят) → `{Поле: "Маршрут"}`;
9. один и тот же сотрудник стоит два этапа подряд (правило команды сверх кейса) → `{Поле: "Маршрут"}`;
10. поле с `ТолькоПоложительное = Истина` и `ТипПоля <> Число` → предупреждение в тот же массив (флаг имеет смысл только у числа).

Плюс `ОшибкиФормата(ПроверяемоеЗначение, ТипПоля, ТолькоПоложительное)` — используется проверкой заполнения документа: число меньше нуля при флажке, пустая дата.

### `ПроверитьИСохранитьШаблон(Вид) → Массив {Поле, Текст}`
- вызывает `ПроверитьШаблон`;
- если ошибок нет → `СтатусНастройки = Перечисления.СтатусыНастройкиВида.Готов`, иначе `Черновик`;
- пишет вид в транзакции; возвращает тот же массив (пустой = сохранено и «Готов»);
- для формы: вывод ошибок — `СообщениеПользователю` с привязкой к полю (делает Денис, функция только возвращает массив).

### `ВидыДляСоздания(Категория = Неопределено) → ТаблицаЗначений`
Колонки `Вид`, `Наименование`, `Категория`. Только `СтатусНастройки = Готов`; если `Категория` передана — отбор по категории. Используется формой выбора вида (Денис) и тестами (Дамир).

### `ВыгрузитьВидВJSON(Вид) → Строка` / `ЗагрузитьВидИзJSON(ТекстJSON) → СправочникОбъект.ВидыДокументов`
`ЗаписьJSON`/`ЧтениеJSON` (платформенные, без внешних библиотек). Состав: имя, категория, префикс, поля (идентификатор, заголовок, тип, обязательность, скрытость, только положительное, значения списка), маршрут (номер, название, согласующий по ФИО+email, срок). Загрузка создаёт **новый** вид и прогоняет `ПроверитьШаблон`.

### `СкопироватьВид(Вид, НовоеНаименование) → СправочникСсылка.ВидыДокументов`
Копия со всеми полями, значениями и маршрутом; новый вид получает статус `Черновик`.

## Документ `ДокументСЭД`

### Модуль объекта: `ОбработкаПроверкиЗаполнения(Отказ, ПроверяемыеРеквизиты)`
- `ВидДокумента` обязателен; `Ответственный` обязателен (без него документ нельзя отправить на согласование);
- `Руководитель` при пустом значении подставляется из карточки ответственного (вызывается также из формы при изменении ответственного);
- значения полей из ТЧ `ЗначенияПолей` → проверка обязательности и формата (`ОшибкиФормата`);
- при статусе **не** `Черновик` и **не** `НаДоработке` — любая правка запрещена (`Отказ = Истина`), кроме служебных полей статуса/этапа/цикла.

### Модуль объекта: `ПриЗаписи(Отказ)` — нумерация
Номер = `Префикс вида` + порядковый номер в пределах вида, `Д-0001`, `ВХ-0001`; счётчик считается по уже записанным документам этого вида (без пересечения номеров разных видов).

### Модуль менеджера: `РуководительОтветственного(Ответственный) → СправочникСсылка.Сотрудники`
Возвращает `Ответственный.Руководитель`; пустая ссылка, если руководитель не задан.

## Справочник `ВидыДокументов`

### Модуль объекта: `ПередЗаписью(Отказ)`
- при создании `СтатусНастройки = Черновик`;
- `Наименование` и `Категория` не подменяются «умолчаниями» — за корректность отвечает `ПроверитьШаблон`.

## Справочник `Сотрудники`
Связь с пользователем ИБ — реквизит `Пользователь` (имя пользователя, `ИмяПользователя()`); справочника «Пользователи» в конфигурации нет (БСП не используем). Это архитектурное решение, записано в `docs/02-arhitekturnye-resheniya.md`.

## Правила кодирования
- BSL: UTF-8 **с BOM**, отступ — табы.
- Области: `#Область ПрограммныйИнтерфейс` / `#Область СлужебныеПроцедурыИФункции`.
- Никаких чисел-констант в коде (таймауты, порты — константы конфигурации).
- Запросы — по стандарту 1С: без обращений к полям регистратора через точку, индексы под условия отбора.
- Комментарии — по-русски, по делу; не описывать очевидное.
