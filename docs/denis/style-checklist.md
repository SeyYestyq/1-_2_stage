# Чек-лист оформления форм

Используются элементы стиля из сборки `damir`: пары
`СтатусЧерновикЦвет/Фон`, `СтатусНаСогласованииЦвет/Фон`,
`СтатусСогласованЦвет/Фон`, `СтатусОтклоненЦвет/Фон`,
`СтатусНаДоработкеЦвет/Фон`, `АкцентПродукта`.
Палитра этой интеграцией не меняется. Значения находятся в `ДокМаршрут/StyleItems`.

Это локальный чек-лист для команды, не утверждённый стандарт организаторов.
Все пункты проверяются в платформе; наличие списка не означает «25/25 пройдено».

- [ ] 1. Заголовок формы понятен без пояснения разработчика.
- [ ] 2. Команды названы глаголами.
- [ ] 3. Основная команда выделена.
- [ ] 4. Действие по умолчанию не приводит к случайному отказу.
- [ ] 5. Недоступные действия имеют пояснение.
- [ ] 6. Категория выбирается раньше вида.
- [ ] 7. В выборе только готовые виды категории.
- [ ] 8. Обязательные поля отмечены.
- [ ] 9. Поля идут в заданном администратором порядке.
- [ ] 10. Тип редактора соответствует типу поля.
- [ ] 11. Список значений ограничен владельцем.
- [ ] 12. Ошибки показываются одновременно.
- [ ] 13. Каждое сообщение связано с полем.
- [ ] 14. Ошибка не меняет статус документа.
- [ ] 15. Ответственный обязателен.
- [ ] 16. Руководитель подставляется и может быть исправлен.
- [ ] 17. Статус виден в шапке.
- [ ] 18. Текущий согласующий заметен.
- [ ] 19. Этапы различимы без цвета.
- [ ] 20. История соответствует маршруту и циклу.
- [ ] 21. Прямых RGB в коде форм нет.
- [ ] 22. Четыре отбора совместимы.
- [ ] 23. Утрата введённых данных требует подтверждения.
- [ ] 24. На 1280×768 нет горизонтальной прокрутки.
- [ ] 25. Полный сценарий доступен с клавиатуры.
