# Приёмка интерфейса

Статус: ручные проверки ниже **не выполнены** — платформы 1С на машине нет.
Запускать на тестовой ИБ 8.3.24 после загрузки конфигурации из файлов.

1. Открыть список документов: восемь видимых колонок, доступны создание,
   открытие документа и кнопка «Мои согласования».
2. Установить одновременно категорию, вид, ответственного и статус.
   Выдача соответствует пересечению условий. Сбросить быстрые отборы:
   пользовательские настройки списка остаются на месте.
3. Создать документ. До выбора категории выбор вида недоступен; после выбора
   предлагаются только непомеченные на удаление готовые виды этой категории.
4. Проверить три разных вида с полями «Строка», «Число», «Дата», «Выбор из списка».
   Порядок совпадает с `Порядок` в виде. Длинные заголовки не ломают форму.
   Пустая обязательная сумма даёт сообщение у поля и не позволяет записать документ.
   Все ошибки выводятся за один проход. Клик по сообщению переводит фокус в поле.
5. Выбор из списка показывает значения только владельца-поля. Подстановка чужого
   значения должна блокироваться серверной проверкой формы.
6. Выбрать ответственного с руководителем, затем без руководителя: подставляется
   соответствующее значение, прежний руководитель не остаётся.
7. Заполнить и записать документ. Закрыть и открыть снова: все типы значений сохранены.
   Скрыть одно поле в виде, повторить запись документа: значение скрытого поля остаётся
   в табличной части. Вернуть видимость: старое значение вновь отображается.
8. В новом документе изменить категорию/вид: отмена подтверждения сохраняет поля;
   подтверждение сбрасывает только поля вида. В записанном документе вид фиксирован.
9. Проверить карточку документа с маршрутом: согласованный этап — ✓ и зелёный,
   текущий — ● и синий, ожидающий — ○ и серый, отклонённый — ✕ и красный.
   Проверить отказ и повторный цикл: состояние определяется решением снимка.
   История показывает все циклы и сортируется по циклу и дате решения.
10. В названии этапа и комментарии использовать `<`, `&`, кавычки: текст отображается
    как текст, не исполняется как HTML. У HTML нет внешних ресурсов и скриптов.
11. В «Моих согласованиях» видны только документы на согласовании, где текущий
    сотрудник — согласующий. Отсутствующая или неоднозначная привязка пользователя
    даёт пустую таблицу с пояснением. Двойной щелчок открывает карточку.
12. Проверить формы в тонком и веб-клиенте, 1280×768: нет горизонтальной прокрутки,
    работа с клавиатуры последовательна. Проверить разрешение цветов элементов стиля
    в HTML на целевой платформе. При необходимости поправить адаптер `CSSЦвет`.

Отправка, решения и печать проверяются после подключения контрактов владельцев.
Сейчас кнопки отключены и статус не меняют. Фильтрация интерфейса не заменяет права
доступа: роли и серверные проверки движка остаются ответственностью владельцев.

## Проверки без платформы

Выполнено при подготовке ветки:

- `python3 tools/gen_config.py`: повторная генерация не изменила файлы.
- `python3 tools/check_config.py`: 65 XML, 141 уникальный UUID, проверки пройдены.
- Четыре изменённых модуля разобраны `bsl-parser 0.29.0` / `antlr4 0.2.0`
  на Java 17: синтаксических ошибок нет. Это проверка грамматики, а не компиляция
  в платформе: доступность методов и свойств формы она не подтверждает.
- `python3 -m unittest discover -s tools/tests -v`: регрессии генератора.

Для проверки XML требуется `xmllint` (`libxml2-utils`). На машине проверки бинарник
был распакован в `/tmp`, системные пакеты не изменялись.
