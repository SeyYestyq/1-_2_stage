# Приёмка после интеграции с damir

**Эти проверки в платформе ещё не выполнены.** Загрузить в отдельную тестовую ИБ
учебной 1С 8.5.1.1150 папку `ДокМаршрут/`, обновить конфигурацию БД, запустить
Предприятие. Порядок запуска — `ДокМаршрут/README.md`. Использовать демо-данные;
для проверки согласования сопоставить пользователей ИБ с сотрудниками.

1. Создать документ: сначала категория, затем только готовые виды этой категории.
   Нельзя выбрать помеченный на удаление или черновой вид, в том числе вводом строки.
2. Три демо-вида открываются одной формой. Поля соответствуют их типам и порядку;
   у даты есть календарь, у числа числовой редактор, у списка — свои значения.
3. В новом документе сменить категорию/вид: отмена сохраняет прежние данные,
   подтверждение очищает поля вида. Повторно выбрать прежний вид: значения не стираются.
4. Оставить обязательную сумму и ответственного пустыми: черновик можно записать,
   отправка заблокирована. Все ошибки видны одновременно. Клик по сообщению
   устанавливает фокус в нужное поле, статус остаётся «Черновик».
5. Ввести число с дробной частью, ноль, отрицательное число, дату и значение списка,
   записать, закрыть и открыть. Значения должны сохраниться без потери точности.
   Отдельно проверить ввод нуля вместо пустого числового поля.
6. Проверить старые строковые значения чисел/дат, включая неверный формат.
   Открытие не изменяет исходные данные; исправление записывается только явно.
7. Скрыть поле вида, открыть и перезаписать документ, снова показать поле:
   старое значение сохранилось. Аналогично проверить неизвестное поле старого документа.
8. Выбрать ответственного с руководителем, затем другого без руководителя,
   затем очистить ответственного: прежний руководитель не остаётся.
9. В сохранённом виде (включая черновой) нажать «Предпросмотр формы».
   Отображается тот же набор редакторов. Закрытие не создаёт документ в ИБ;
   команды записи, отправки, печати не выполняются. Для изменённого незаписанного
   вида форма просит сначала сохранить изменения.
10. Заполнить документ и отправить: реальный движок переводит статус и создаёт
    маршрут. После отмены/ошибки записи отправка не вызывается по старым данным.
11. Под текущим согласующим выполнить решение, проверить следующий этап,
    историю и оформление. Чужой пользователь не принимает решение.
12. Отклонение без комментария и отмена ввода не дают решения. Непустой комментарий
    сохраняется в истории. Возврат на доработку позволяет исправить поля и отправить повторно.
13. Печать и уведомления используют значения новых редакторов. Реальные письма
    отправлять только на подготовленные тестовые адреса, SMTP не нужен для офлайн-проверок.
14. Четыре фильтра одновременно дают пересечение условий. «Мои задачи» добавляет
    текущего согласующего и статус «На согласовании», сохраняя выбранные отборы.
15. Проверить тонкий и веб-клиент, 1280×768, длинные названия полей, работу с клавиатуры.

## Оставшиеся вопросы владельцам

- `Согласование.ЭтоАктивныйСогласующий` разрешает демо-решения без привязки,
  когда ни у одного сотрудника не задан пользователь ИБ. `ТекущийСотрудник`
  выбирает первое совпадение при дублирующемся логине. Перед общей приёмкой
  капитану нужно подтвердить режим демо и проверить привязки.
- В сборке одна роль «ПолныеПрава». Разделение прав участников не проверялось.
- Проверка формата ядра принимает отрицательное число; отдельного признака
  «Только положительное» у полей этой сборки нет. Решение о таком правиле — владельцу ядра.
- Базовая печать использует локальный запуск полученного файла, отправка письма —
  синхронное подтверждение. Эти сценарии нужно отдельно проверить в веб-клиенте.
- Набор статусов и контракт ошибок ядра отличается от старого `spec/contracts.md`
  ветки `angelina`. Текущая ветка использует фактические функции сборки `damir`.
