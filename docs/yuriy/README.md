# Печать и уведомления ДокМаршрута

Ветка `yuriy`. За основу взята `origin/denis` (`fe44295`), которая включает сборку `damir`. На момент начала работы ветки `main` на сервере не было.

## Карточки 20–23

- **20. Настройки почты.** В разделе «Сервис» откройте «Настройки почты», заполните сервер, порт, таймаут, SSL, отправителя и при необходимости логин и пароль приложения. «Проверить отправку» сохраняет настройки и отправляет письмо на адрес отправителя. Пустое поле пароля оставляет прежнее значение, сохранённое значение не выгружается обратно в форму. Тестовая попытка попадает в журнал.
- **21. Печатная форма.** `ПечатьДокументов.СформироватьТабличныйДокумент(ДокументСсылка)` возвращает заполненный табличный документ. Макет включает шапку, участников, поля в порядке настройки вида, этапы с решениями текущего цикла и подвал. Скрытые поля не печатаются. В интеграционной сборке описание полей берётся из табличной части `Вид.Поля`, поскольку экспорт `КонструкторВидов.ПоляВида` в `denis` отсутствует.
- **22. Письмо с вложением.** `СформироватьPDF` возвращает двоичные данные из потока в памяти. Для карточки документа сохранён существующий интерфейс `СформироватьВложениеПечатнойФормы`. Учебная лицензия блокирует сохранение табличного документа в PDF, при таком ограничении используется HTML с теми же данными. Согласование после записи вызывает существующую `ОтправитьПоСобытию`, которая передаёт управление `ПриСменеСтатуса`. Адреса берутся у ответственного и его руководителя, повторяющиеся адреса исключаются. В файловой базе отправка синхронная, в клиент-серверной запускается фоновое задание.
- **23. Ошибки почты.** В журнале уведомлений включите отбор «Только ошибки». Каждая попытка получает отдельный идентификатор, ошибки также идут в журнал регистрации. Сохранённый статус документа не зависит от ответа SMTP. Порт и таймаут задаются константами через форму.

## Что проверено

- `py -X utf8 tools/check_dump.py` и `py -X utf8 -m unittest discover -s tools/tests -v`.
- XML загружен в отдельную учебную файловую ИБ 8.3.27.1508. Для этой проверки в копии заменён только параметр интерфейса 8.5, которого нет в 8.3. Конфигуратор обновил схему, проверка серверных модулей и тонкого клиента завершилась без ошибок.
- В режиме Предприятия сформированы табличные документы для шести записей трёх демо-видов. Учебная платформа вернула HTML-вложения из-за ограничения экспорта PDF.
- На локальном SMTP-сервере с тестовыми адресами проверены отказ соединения и отказ аутентификации `535`. При отказе аутентификации после записи статуса «Согласован» в журнале были отдельные ошибки ответственного и руководителя. После замены пароля оба адресата получили HTML-письма с вложением и статусом «Согласован».

Для приёмки нужен прогон на целевой платформе с доступным экспортом PDF, реальные тестовые ящики и проверка клиент-серверного режима. Адреса, пароли приложения и токены храните вне Git. После успешного прогона можно записать резервное видео для карточки 24.
