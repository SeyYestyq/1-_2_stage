## Как читать

Каждое утверждение помечено источником:

- **[КЕЙС]** — требование текста кейса, ТЗ или вебинара 16.11;
- **[МАТЕРИАЛЫ]** — решение, уже зафиксированное в материалах команды (модель данных, личный документ);
- **[СОВЕТ МК]** — совет с мастер-класса 30.10 или 06.11, не требование кейса;
- **[ДОПУЩЕНИЕ]** — внутренняя договорённость команды, не из кейса;
- **[ПРЕДЛОЖЕНИЕ]** — предложение автора протокола, требует подтверждения капитана или команды.

Где решение не принято, так и написано. Додумывать за капитана протокол не должен.

1. Нужно письменное подтверждение организаторов — это блокер, который снимает не команда. [МАТЕРИАЛЫ]

**Статус: предложение. Нужно подтверждение капитана до 18.11 12:00.** Если капитан выбирает 8.5 —

## 3. Инструмент разработки: Конфигуратор или 1С:EDT

### Что известно (проверено 18.11.2026)

- 1С:Напарник (ревью кода по стандартам, помощь с сообщениями коммитов, работа с Git) работает
  **только в 1С:EDT**; в Конфигураторе его нет. [СОВЕТ МК 30.10 — не требование кейса]
- На странице подключения `code.1c.ai/easystart`: начиная с 1С:EDT 2025 Напарник входит в дистрибутив,
  отдельно ставить не нужно; плагин работает с EDT версий 2023–2026; бесплатен до 1 февраля 2027 года.
- Токен каждый участник получает сам на портале 1С — `portal.1c.ru/access-tokens`, у каждого свой.
  Ввод в EDT: Window → Preferences → 1C:Workmate, поле «User Token», кнопка «Verify».
- Нужна ли для токена подписка ИТС или достаточно учётной записи портала 1С — на странице прямо не
  сказано. **Не выяснено.**

### Сравнение

| Критерий | Конфигуратор + выгрузка в файлы | 1С:EDT |
|---|---|---|
| Порог входа | платформа уже включает Конфигуратор | отдельная установка, проект, привязка базы |
| Git | выгрузка в файлы, коммит папки; служебные файлы меняются у всех | проект EDT целиком под Git, встроенная работа с ветками |
| Ревью по стандартам | вручную, глазами | 1С:Напарник: замечания по стандартам, подсказки по коммитам |
| Соответствие критериям оценки | «Архитектура» и «Производительность» — по 6 баллов, ревью кода к 02.12 требует «0 критичных замечаний» | то же, но с автоматической подсказкой, где нарушено |
| Риск | низкий: инструмент штатный, ничего не ставим | установка EDT на macOS не проверена; в материалах опыта нет |
| Сроки | сразу | 1–2 часа на установку и первый проект, если всё пойдёт гладко |

### Предложение

**Основной инструмент — 1С:EDT с Напарником**, потому что ревью кода по стандартам входит в критерии
оценки и в чек-лист приёмки (карточка 08), а Напарник — единственный способ делать это не вручную.

Условия, при которых предложение действует:

1. EDT ставится на машину Ангелины и открывает проект без ошибок — проверить 18.11 до 18:00.
   Если установка не идёт, решение откатывается на Конфигуратор: срок каркаса (20:00) важнее инструмента.
2. Токен Напарника получен; если для него требуется подписка ИТС, которой у участников нет, —
   Напарник не используем, работаем в EDT без него либо в Конфигураторе.
3. Формат хранения в Git фиксируется один раз и не меняется: смешивать проект EDT и выгрузку
   Конфигуратора в одном репозитории нельзя.

**Статус: предложение. Нужно подтверждение капитана до 18.11 12:00**; техническая проверка
установки — на Ангелине, до 18.11 18:00.

Отдельно: даже при выборе Конфигуратора Напарник остаётся доступен как внешний ревьюер — но только
в EDT, поэтому «Конфигуратор + Напарник» невозможен. [СОВЕТ МК 30.10]

## 5. Следствия, которые нужно объявить команде

1. Никто, кроме Ангелины, не создаёт объекты метаданных и не меняет корень конфигурации.
   Оболочки новых объектов — заявка в отчёте или в чат, оболочка в ветке `angelina` в тот же вечер,
   слияние капитаном первым. [МАТЕРИАЛЫ, модульный план раздел 3]
2. Статусы и события — только значения перечислений; ошибки — только массив структур `{Поле, Текст}`;
   порядок полей — только по реквизиту `Порядок`. Меняются через Ангелину. [МАТЕРИАЛЫ]
3. Документ не проводится: `Posting = Deny`. Любая попытка «сделать статус проведением» — нарушение
   архитектуры и стандарта № 603.
4. Прямых цветов в формах нет — только элементы стиля, имена фиксированы.
5. Служебные файлы выгрузки в личные коммиты не включаются.
