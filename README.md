# ДокМаршрут — конфигурация СЭД, модуль «Ядро и конструктор видов»

Конфигурация 1С:Предприятие 8.3 для продукта «ДокМаршрут» (кейс «Кодерлайн», трек 1С).
Администратор создаёт виды документов прямо в режиме предприятия, не открывая Конфигуратор
и не меняя конфигурацию.

Ключевая формула архитектуры: **один универсальный документ, виды и поля — данные,
маршрут — снимок в документе.**

Ветка модуля — `angelina`. В `main` сливает только капитан, в порядке
`angelina → maksim → yuriy → denis → damir` (модульный план, раздел 4).

## Честный статус проверки

Что проверено на этой машине (`python3 tools/check_config.py`):

- все XML — well-formed (`xmllint`);
- все `uuid` уникальны, повторов нет;
- все ссылки по именам разрешаются: `cfg:CatalogRef.*`, `EnumRef.*`, `DocumentRef.*`,
  `ChartOfCharacteristicTypesRef.*`; объявления `<Form>` ведут на существующие файлы форм;
- состав корня `Configuration.xml` совпадает с набором объектов на диске, порядок типов
  в `ChildObjects` соблюдён;
- у каждого объекта заполнены `Name` и `Synonym`, у табличных частей есть `InternalInfo`
  с `GeneratedType`.

Что **не** проверено и почему:

- **выгрузка не загружалась в платформу** — 1С:Предприятие на этой машине не установлено
  (macOS, Apple Silicon). Формат собран по спецификации выгрузки версии 2.17 и по реальным
  эталонным дампам Конфигуратора, но «соберётся ли база с первого раза» не подтверждено;
- модули `.bsl` не выполнялись: синтаксис и поведение проверяются в платформе или тестами
  Дамира (YAxUnit). Код написан по контрактам и стандартам 1С, «зелёный» статус появится
  только после прогона в базе;
- формы открывались только как XML, интерактивно их никто не нажимал;
- сохранение вида, нумерация, проверка шаблона и перенос в JSON реализованы в коде, но на
  данных не прогонялись.

Запасной путь, если загрузка выгрузки не пройдёт: собрать объекты вручную в Конфигураторе по
`docs/03-karta-obektov.md` и вставить модули `.bsl` — пути в дереве совпадают
(`CommonModules/<Имя>/Ext/Module.bsl`, `Documents/<Имя>/Ext/ObjectModule.bsl` и т. д.).

## Структура выгрузки

Порядок каталогов соответствует выгрузке конфигурации «в файлы» (Конфигуратор: «Конфигурация →
Выгрузить конфигурацию в файлы»). Корень репозитория — папка с `Configuration.xml`.

```
Configuration.xml                                  свойства конфигурации и список объектов
Languages/Русский.xml
Enums/<Имя>.xml
Catalogs/<Имя>.xml
Catalogs/<Имя>/Ext/ObjectModule.bsl
Catalogs/<Имя>/Forms/<Форма>.xml                   дескриптор формы
Catalogs/<Имя>/Forms/<Форма>/Ext/Form.xml          тело формы
Catalogs/<Имя>/Forms/<Форма>/Ext/Form/Module.bsl   модуль формы
ChartsOfCharacteristicTypes/<Имя>.xml
Documents/<Имя>.xml
Documents/<Имя>/Ext/ObjectModule.bsl
Documents/<Имя>/Ext/ManagerModule.bsl
Documents/<Имя>/Forms/...
InformationRegisters/<Имя>.xml
Constants/<Имя>.xml
CommonModules/<Имя>.xml
CommonModules/<Имя>/Ext/Module.bsl
Roles/<Имя>.xml
Roles/<Имя>/Ext/Rights.xml
Subsystems/<Имя>.xml
StyleItems/<Имя>.xml
spec/metadata.json                                 спецификация состава (источник истины)
spec/contracts.md                                  контракты функций
tools/gen_config.py                                генератор выгрузки из спецификации
tools/check_config.py                              проверки без платформы
docs/                                              документы команды
```

Пути модулей в дереве совпадают с тем, что ожидает платформа при загрузке, поэтому `.bsl` можно
готовить отдельно от XML и вставлять в нужный узел дерева. Служебные файлы, которые меняются
у всех при каждой выгрузке (`ConfigDumpInfo.xml`), в личные коммиты не включаются — их обновляет
Ангелина в своей ветке (предложение модульного плана; точный перечень зависит от инструмента).

## Как загрузить в 1С

Порядок для инструмента «Конфигуратор + выгрузка в файлы». В репозитории выставлен режим
совместимости `Version8_3_24`, поэтому нужна платформа не ниже 8.3.24.

1. Установить платформу 1С:Предприятие 8.3 (не ниже 8.3.24).
2. Создать пустую информационную базу без конфигурации. Для демо в материалах предполагается
   файловая база (в ТЗ это допущение, окончательный выбор — за Юрием, `docs/06-voprosy-komande.md`).
3. Открыть базу в Конфигураторе.
4. «Конфигурация» → «Загрузить конфигурацию из файлов» → указать **корень репозитория** (папку
   с `Configuration.xml`) → подтвердить замену конфигурации.
5. «Конфигурация» → «Обновить конфигурацию базы данных» (F7), принять изменения.
6. Сверить список объектов с `docs/03-karta-obektov.md`: количество и имена должны совпасть.
7. Создать пользователей информационной базы и заполнить справочник «Сотрудники»: реквизит
   «Пользователь ИБ» — имя пользователя базы, по нему работают отборы «мои согласования»
   (справочника «Пользователи» в конфигурации нет, БСП не используется).
8. Выдать роли: администратору видов — «Администратор видов», остальным — «Сотрудник» или
   «Согласующий». «ПолныеПрава» — только для демо и настройки.

Тот же порядок из командной строки (пример из документа о канбан-доске; в материалах приведён
для Windows):

```
1cv8 DESIGNER /F "<путь к базе>" /LoadConfigFromFiles "<папка выгрузки>" /UpdateDBCfg /Out load.log
```

Если выбран 1С:EDT, шаги 2–5 заменяются импортом проекта из папки репозитория и обновлением
связанной информационной базы.

## Правила репозитория

- Каждый меняет только свои объекты (модульный план, разделы 1 и 7). Формы внутри объектов
  Ангелины правит Денис — только файлы форм, не сам объект.
- `tools/gen_config.py` перезаписывает XML метаданных из `spec/metadata.json`. Правите реквизиты
  руками в Конфигураторе — перенесите изменение в спецификацию, иначе следующая генерация его
  потеряет. Модули `.bsl` и тела форм генератор не трогает.
- Перед коммитом: `python3 tools/gen_config.py && python3 tools/check_config.py`.
- Кодировки: `.bsl` — UTF-8 с BOM, отступы табуляцией; `.xml` — UTF-8 без BOM.

## Открытые вопросы

Полный перечень с адресатами и сроками — `docs/06-voprosy-komande.md`. Коротко:

1. Версия платформы и инструмент не подтверждены капитаном (срок 18.11 12:00), см. `docs/01`.
2. Хостинг репозитория и защита `main` не определены.
3. Состав ТЧ `МаршрутСнимок` и реквизит «Срок этапа» ждут подтверждения Максима.
4. `Сотрудники.ИДПользователяMAX` дублирует регистр `ПользователиMAX` — предлагается оставить
   только регистр.
5. Категория демо-вида («Входящий», «Исходящий», «Договорной») — решается с Денисом до генпрогона.
6. XML-выгрузка не загружалась в платформу: платформы на машине нет.
